## 简历 HTML 结构相似性分组

- 目录内共 2484 个 resume{0..2483}.html，均为简历系统导出的 div 片段（无 doctype/html/body），约 37 MB。
- 判定方法：lxml 解析 DOM → 去掉文本/随机 id/内联 style/纯排版标签(b,u,i,font,br…) → 保留「标签名 + class + 层级」→ 折叠同构重复子树 → 得结构骨架指纹。指纹相同为精确版式组；不同指纹按节点与父子路径集合的 Jaccard ≥ 0.75 归入结构家族。
- 结论：267 种精确版式（112 组含 ≥2 文件，覆盖 2329 份）；57 个结构家族（14 个 ≥10 文件，覆盖 2371 份）；799 种章节序列；42 种根 class 主题（默认/MPR/LCA/RNA）。

## PyTorch 简历-岗位适配度模型（代码交付）

- 用户要求：不在数据根目录放 .py，全部代码输出到子目录由用户自行复制；需说明文件组织格式。交付目录 `jobfit_project/`（包 `jobfit/`，13 个模块 + configs/default.json + requirements.txt + examples/demo_api.py + tests/smoke_test.py），根目录保持无 .py。
- 标签数据：`tag.csv` 无表头，两列 `resume_id, 岗位类别`（标签带前导空格），2484 行对应 24 类（IT 120 ... BPO 22），类别分布不均；**没有岗位 JD 文本**。因此把 24 个类别当作岗位，岗位塔 = 可学习原型 + 由训练语料类内 tf-idf 差值生成的"伪 JD"文本编码；支持 jobs.csv / --jd-text 传入真实 JD。
- 模型：字段感知 TextCNN（unigram+bigram、tf-idf 加权池化、segment embedding）+ 数值特征 MLP → L2 归一化简历向量；岗位向量同理；打分层 = cos/可学习温度 + 交叉交互 MLP + 岗位先验偏置 → logits[B,24]。同一 logits 矩阵：按行排=一人多岗，按列排=一岗多人。
- 训练：分层+同组不跨集合切分（content_duplicate=yes 的 24 份强制进 train，避免近重复泄漏）；词表/idf/数值标准化只在 train 拟合；CE+label smoothing+类别频率倒平方根加权+难负样本 margin；AdamW 预热余弦、早停。
- 打分：验证集拟合温度 T、Platt(a,b)、z_lo/z_hi 分位锚点。默认主分 `spread = 100*clip((z-z_lo)/(z_hi-z_lo))`（非饱和，0-100 铺开）；`platt` 概率分会饱和在 99.x，故另存为 match_probability；另有 share / percentile 模式与 job_share、percentile 字段。解释用字段消融 + 命中关键词。
- 全量实测（30 轮早停于 15-21 轮）：测试集 acc 0.848、macro-F1 0.789、top3 0.909、ECE 0.051；一岗选人 P@10 0.858、nDCG@10 0.886、MAP 0.824。CPU 训练约 7 分钟 / MPS 约 1 分钟。
- 环境注意：本机 Python 3.13 + torch 2.15 装在 /tmp/jobfit_venv；受限沙箱会阻止临时文件删除，导致 torch dynamo 初始化报 "No usable temporary directory"，验证时用项目内 `.runtime/run_check.py` 预置 `tempfile.tempdir` 绕开（不属于交付代码）。`set_seed` 已移除 `use_deterministic_algorithms` 调用以降低该风险。

## 岗位 JD 接口规格与已发现的缺陷（追问"需要什么 JD 文本"）

- 有效路径只有一条：`jobs.csv`（表头 `label,title,jd_text,required_skills`，UTF-8）把真实 JD 绑定到 `tag.csv` 已有的 24 个标签，**且必须重新训练**。data.py:423 在 Corpus 构建期读入，结果写进 checkpoint 的 job_txt_* buffer；只改 CSV 不重训，推理不生效。`label` 写错（不在 24 类内）会被当作新岗位追加，而新岗位无训练样本、无 proto，分数不可信。`job_id` 列代码忽略。
- **重要缺陷**：`--jd-text` / `--jd-file` 走 model.py 的 `custom_job` 分支，使用 `unk_proto` / `unk_bias`；train.py 从未传入 custom_job，这两个参数全程无监督。用正式权重实测 HR 场景：`--job HR` Top5 全 HR（95.9→94.3）；英文 HR JD 走 `--jd-text` Top5 全 ENGINEERING（~55 分）；中文 HR JD 同样全 ENGINEERING（~51 分）。**上一轮"无需重训即可用 --jd-text 打分"的说法已被证伪，需改训练（岗位塔对比学习/随机 JD 增广）才能让零样本新 JD 可用。**
- 语言限制：词表由英文简历语料构建（30002 词，min_df=2），`tokenize('负责招聘与薪酬绩效…')` 返回空列表 → 中文 JD 完全无效。要中文需换分词器或接预训练句向量。示例英文 JD 词表命中率 89–100%。
- 长度：`max_job_len=96` token，超出截断；建议 60–90 词 / 300–500 字符，关键词前置。内容写职责动词、技能工具、证书、年限、学历、领域术语；不要薪资福利地点、HTML、表格。
- 真正的"业务适配度"仍需 `(resume_id, job_id 或 JD 文本, 0-100 分/录用标签)` 三元组（建议每岗 ≥50–100 条、总量千级）做 pairwise 回归或排序损失；现有 `tag.csv` 第 3 列 + `use_score_supervision=true` 只支持"一份简历一个总分"，不是逐 (简历,岗位) 对。
- 新增交付：`jobfit_project/data/jobs.example.csv`（24 行模板，3 行填好示例：ACCOUNTANT / HR / INFORMATION-TECHNOLOGY）。已验证 24 个 label 全部命中、无新增岗位、编码矩阵 (24,96)、最大有效长度 67。模板不在上一次的 zip 内，单独输出给用户复制。
